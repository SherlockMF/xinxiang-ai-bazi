# 心象离线小工具设计（纯前端 / 零联网）

日期：2026-09-05  
状态：待实现  
分支上下文：`fix/bugfixes-and-ai-bazi-analysis`

## 1. 目标与硬限制

在现有「心象」产品之上，新增一版**可独立打开、后续可打 zip 上传**的离线小工具，满足：

- 纯前端：标准 HTML / CSS / JS
- 不能联网：禁止 `fetch`、XHR、外链图片/字体/CDN、WebSocket、SSE、WebRTC
- 资源必须包内：页面、脚本、图片、字体、JSON 均相对路径引用
- 因此不做在线大模型；WASM / 本地跑模型也不做

本阶段**先不打包 zip**，以可迭代源码目录交付；后续再在此基础上优化与打包。

## 2. 方案选择

采用**独立目录 `offline/`**（方案 1）：

- 不改造现有 Taro 主工程运行时
- 直接双击 / 静态服务器打开 `offline/index.html` 即可体验
- 排盘与日签算法从现有前端服务移植，保证体感一致

明确不采用：

- Taro「离线开关」：产物形态不符合「标准 HTML zip」硬限制
- 把现有 React 整站静态化：体积与依赖过重，后期优化成本高

## 3. 产品范围（方案 A：完整仪式感）

### 3.1 保留（全本地）

1. 欢迎页 → 有档案进今日，无档案进生辰
2. 生辰录入（昵称、生日、时辰、性别；不知时辰 → 正午）
3. 心象盘（四柱、日主、五行、喜用、摘要）
4. 今日心象（seed 日签：象名、摘要、宜忌、偈语、色/数/向、行动建议）
5. 问心（快捷问题 + **本地模板回答**，无 API）
6. 签亭（签文卡片 + 收藏列表；页内展示即可）
7. 本心（档案摘要、近几日历史、清数据）

### 3.2 明确不做

- 深度心象解读（原 `/api/bazi/analyze`）
- 感应此刻 LLM（原 `/api/bazi/moment`）
- 在线问心（原 `/api/chat/message`）
- Canvas 海报导出 / 相册保存 / 微信分享（后续可选）
- 任何网络请求与外链资源

### 3.3 合规文案

保留产品既有免责声明气质：遗怀清心之趣，非关休咎，不作决断之凭。

## 4. 信息架构与路由

单页应用，hash 路由：

| 路由 | 页面 |
|------|------|
| `#/` | 欢迎 |
| `#/birth` | 生辰录入 |
| `#/bazi` | 心象盘 |
| `#/today` | 今日心象 |
| `#/ask` | 问心 |
| `#/share` | 签亭 |
| `#/me` | 本心 |

底部 Tab（与现产品一致）：**今日 / 问心 / 签亭 / 本心**。  
生辰、心象盘从流程进入，不占 Tab。

## 5. 数据模型与存储

全部使用 `localStorage`（无同步后端）：

| Key | 内容 |
|-----|------|
| `xinxiang_profiles` | 档案列表（含排盘结果） |
| `xinxiang_active_id` | 当前档案 ID |
| `xinxiang_fortune_{id}_{date}` | 当日日签缓存 |
| `xinxiang_favorites` | 收藏签文 |
| `xinxiang_history` | 近几日观心记录 |

运行时：内存 `AppState`（当前路由、当前档案、今日 fortune）；持久化只走上表。

多档案：MVP 先支持「当前一个主档案 + 可再录入覆盖/追加」；切换 UI 可简化，但存储结构预留列表。

## 6. 算法与问心策略

### 6.1 移植来源（只读逻辑，改为纯 JS 模块）

- `src/services/baziService.ts` + `src/services/birthUtils.ts` → `offline/js/bazi.js` / `birth-utils.js`
- `src/services/fortuneService.ts`（及日签所需祝福/文案工具）→ `offline/js/fortune.js`

保证：同一生辰 + 同一自然日 → 日签稳定可复现。

### 6.2 问心本地模板

文件：`offline/js/ask-templates.js`

| 类型 | 填空来源 | 回答气质 |
|------|----------|----------|
| 此刻之象 | 今日象名 + 日主 + 偈语 | 短、意象化 |
| 内在状态 | 喜用/五行 + 宜忌 | 观察式，不决断 |
| 今日可做 | 宜列表 + 行动建议 | 可执行 1～3 条 |
| 一句提醒 | 偈语 / 色数向 | 一句话收束 |

自由输入：通用模板 + 当日 seed 从文案库抽 2～3 句。  
高风险关键词：本地规则拦截 → 固定安全回复（不联网）。

## 8. 硬限制自检清单（实现与后续打包共用）

- [ ] 无 `fetch` / `XMLHttpRequest` / `WebSocket` / `EventSource` / `RTCPeerConnection`
- [ ] 无 `http(s)://` 资源引用（HTML/CSS/JS/图片/字体）
- [ ] 脚本与样式均为相对路径
- [ ] 打开方式：`file://` 或本地静态服务均可完成主路径
- [ ] 清除数据后主路径可重新录入

## 9. 验收标准（本阶段）

1. 无档案：欢迎 → 生辰 → 心象盘 → 今日，全流程可走通
2. 有档案：刷新后仍落在今日，日签与排盘一致可复现
3. 问心四类快捷问均有本地回答；断网（本就无网）行为不变
4. 签亭可收藏/取消收藏；本心可查看摘要并清数据
5. 代码检索不到联网 API 调用与外链 CDN

## 10. 非目标（显式）

- 本阶段不产出 zip、不上架、不接审核后台
- 不维护与 Taro 主工程的运行时双写；算法以「移植副本」为准，后续若要同步再单独立项
- 不实现服务端 Nest / 智谱相关能力

## 11. 后续可优化（不在本次实现）
